# 이벤트 테스트 케이스 생성

## 디렉토리 구조

```
use_case/event_sheets/
├── template.xlsx          # 공통 템플릿 (기존)
├── cases/
│   ├── 01_fansign_event/         # 팬사인회
│   ├── 02_photo_event/           # 포토회
│   ├── 03_game_event/            # 게임회
│   ├── 04_bakery_event/          # 베이커리 이벤트
│   ├── 05_daily_host/            # 일일점장
│   ├── 06_special_event_gacha/   # 스페셜(가챠)
│   ├── 07_special_event_other/   # 스페셜(가챠 외)
│   ├── 08_videocall_event/       # 영상통화
│   ├── 09_videocall_event_unit/  # 유닛 영상통화
│   ├── 10_videocall_event_individual/ # 개인 영상통화
│   ├── 11_online_twoshot_event/  # 1:1 온라인 투샷회
│   ├── 12_combo_1_2_and_3/       # (1+2부, 3부)
│   ├── 13_combo_1_2_and_3_4/     # (1+2부, 3+4부)
│   └── 14_combo_1_2_3_and_4/     # (1+2+3부, 4부)
```

각 케이스 폴더 내용:

- `README.md`: 테스트 케이스 설명
- `data.json`: 이벤트 데이터
- `output.xlsx`: 렌더링 결과 (실행 시 생성)

## data.json 생성 시 참고 사항

- [pdf-to-json-prompt.md](use_case/event_sheets/pdf-to-json-prompt.md)의 JSON 스키마 준수
- 각 이벤트 타입별 특성에 맞는 필드 구성:
  - 팬사인회: sign_winners, viewing_winners
  - 포토회: per_member
  - 영상통화: per_member, 통화시간 등
- 가상의 아티스트 이름 사용 (TestArtist 등)
- benefits 배열은 각 이벤트 타입에 맞게 구성

## 스크립트 및 검증 도구

### 디렉토리 구조 (추가)

```
use_case/event_sheets/
├── template.xlsx
├── cases/
│   └── ...
├── scripts/
│   ├── run_all.sh        # 전체 케이스 일괄 실행
│   ├── run_single.sh     # 단일 케이스 실행 (수동 테스트용)
│   └── verify.py         # output.xlsx 검증 스크립트
└── README.md             # 전체 테스트 가이드
```

### verify.py 검증 항목

1. **파일 존재 여부**: output.xlsx 생성 확인
2. **시트명 검증**: 예상 시트명과 실제 시트명 비교
3. **기본 렌더링 검증**: 템플릿 변수(`{{`, `{%`)가 남아있지 않은지 확인
4. **에러 메시지 검출**: 렌더링 에러 메시지 포함 여부

### 실행 방법

```bash
# 전체 케이스 실행 및 검증
./scripts/run_all.sh

# 특정 케이스만 실행 (수동 테스트)
./scripts/run_single.sh 01_fansign_event

# 검증만 실행
python scripts/verify.py

# 특정 케이스 검증
python scripts/verify.py 01_fansign_event
```

### 검증 결과 출력 예시

```
[PASS] 01_fansign_event: 시트 1개 (story-template → 1부 이벤트)
[PASS] 12_combo_1_2_and_3: 시트 2개 (1부2부 이벤트, 3부 이벤트)
[FAIL] 03_game_event: 시트명 불일치 (expected: 게임회, actual: story-template)
```
